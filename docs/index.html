1. บทนำและภาพรวมระบบ

MPIR Lab Suite ถูกพัฒนาขึ้นเพื่อยกระดับการบริหารจัดการห้องปฏิบัติการวิทยาศาสตร์ของฝ่ายวิจัยและนวัตกรรม โดยแบ่งเป็น 2 ระบบที่ทำงานเชื่อมโยงฐานข้อมูลเดียวกัน:

Lab Book+ (Lab Equipment LogBook)

เน้นการจองเครื่องมือวิทยาศาสตร์ การบันทึกเวลาใช้งานจริง (Actual Usage Tracking) การจัดการคิวไม่ให้ทับซ้อน และการสแกน QR Code หน้าเครื่อง

MPIR Lab Care+

เน้นการดูแลรักษาเครื่องมือ วางแผนสอบเทียบ (Calibration Plan) บันทึกประวัติซ่อม วิเคราะห์งบประมาณ และจัดเก็บเอกสารใบสั่งซื้อ (PO/Cert) เข้าสู่ IndexedDB

Real-time Cross-Tab Synchronization: ทั้งสองระบบสามารถเปิดทำงานพร้อมกันคนละแท็บบนบราวเซอร์ และข้อมูลจะซิงค์หากันอัตโนมัติแบบเรียลไทม์ผ่าน Window Storage Event Bus

2. การเริ่มต้นใช้งานและการตั้งค่าส่วนบุคคล

2.1 บัญชีผู้ใช้งานเริ่มต้น

ระบบมีชุดข้อมูลจำลองตั้งต้น (Seed Data) พร้อมบัญชีผู้ใช้งานที่สามารถทดลองใช้งานได้ทันที:

อีเมล / ชื่อผู้ใช้ รหัสผ่านเริ่มต้น บทบาท (Role) คำอธิบายสิทธิ์การใช้งาน Action
admin@lab.com (หรือ admin) admin321 Administrator สิทธิ์สูงสุด จัดการเครื่องมือ ผู้ใช้งาน และสำรองกู้คืนระบบ
user@lab.com (หรือ user) user123 Standard User จองเครื่องมือ บันทึกการใช้งานจริง บันทึกงานซ่อมบำรุง

2.2 การเข้าสู่ระบบ

  1. เปิดไฟล์ index.html หรือ CarePlus.html ผ่านเว็บเบราว์เซอร์
  2. กรอก Username โดยไม่ต้องพิมพ์ @lab.com (ระบบมีป้ายกำกับอัตโนมัติ) หรือพิมพ์อีเมลเต็มรูปแบบ
  3. กรอก Password แล้วกดปุ่ม Login
  4. ระบบจะส่งเสียงสังเคราะห์ตอบรับ (Success Chime) และพานำเข้าสู่หน้าแดชบอร์ดหลักทันที

2.3 การสลับระบบ (Quick Switcher)

บนแถบเมนูด้านบน (Navbar) มีปุ่มลัดสำหรับสลับระหว่างสองระบบได้ในคลิกเดียว:

  • ในหน้า Lab Book+: คลิกปุ่ม Lab Care+ เพื่อเปิดระบบบำรุงรักษา
  • ในหน้า Lab Care+: คลิกปุ่ม Lab Book+ เพื่อกลับสู่ระบบจองเครื่องมือ

2.4 การปรับโหมดมืด/สว่าง และเปิด-ปิดเสียงแจ้งเตือน

  • ปุ่มสลับโหมดมืด (Dark / Light Theme): ไอคอน สลับธีมหน้าจออย่างถนอมสายตา สีจะซิงค์กันข้ามทุกหน้าจอ
  • ปุ่มควบคุมเสียง (Audio Mute Toggle): ไอคอน เปิด-ปิดเสียงเอฟเฟกต์การกดปุ่มและการแจ้งเตือน เพื่อความเงียบสงบในห้องปฏิบัติการ

3. คู่มือการใช้งาน Lab Book+ (Lab Equipment LogBook)

3.1 หน้าปฏิทินและการตรวจเช็กคิวเครื่องมือ

หน้าแรกของ Lab Book+ รวบรวมปฏิทินแบบโต้ตอบ (Interactive FullCalendar) แสดงมุมมอง เดือน, สัปดาห์ และวัน โดยมีสีแสดงสถานะการใช้งานอย่างชัดเจน:

  • Booked (สีน้ำเงิน): รายการจองที่รอการใช้งานตามกำหนด
  • In Use (สีเหลืองกระพริบ): เครื่องมือที่กำลังเปิดใช้งานจริงอยู่ขณะนี้
  • Finished (สีเขียว): ใช้งานเสร็จสิ้นและส่งคืนเรียบร้อยแล้ว

3.2 รายละเอียดฟอร์มการจองเครื่องมือวิทยาศาสตร์ (Exhaustive Booking Form Guide)

เมื่อคลิกปุ่ม "+ Book Equipment" หรือคลิกบนช่องว่างในตารางปฏิทิน ระบบจะเปิดหน้าจอแบบฟอร์มการจอง ซึ่งประกอบด้วยฟิลด์และตัวเลือกดังนี้:

ฟิลด์ / ปุ่มควบคุม ประเภทข้อมูล รายละเอียดและการทำงาน
Area / Building Dropdown เลือกอาคารหรือห้องปฏิบัติการที่เครื่องมือตั้งอยู่ ระบบจะกรองรายชื่อเครื่องมือในช่องถัดไปให้ตรงกับห้องทันที
Equipment Dropdown เลือกเครื่องมือวิทยาศาสตร์ที่ต้องการจอง พร้อมมีป้ายแสดงสถานะความพร้อม เช่น Ready หรือ Maintenance
Start Time datetime-local Smart Default: ระบบจะปัดเศษเวลาขึ้นเป็นต้นชั่วโมงถัดไปให้อัตโนมัติ (เช่น 10:15 น. ปรับเป็น 11:00 น.)
End Time datetime-local Smart Default: ระบบตั้งค่าเริ่มต้นเป็น 2 ชั่วโมงถัดไปจากเวลาเริ่มต้นโดยอัตโนมัติ
Project Code text รหัสโครงการวิจัยหรืองานทดลอง (เช่น RD-2026-MP01) เพื่อจัดกลุ่มงบประมาณและตรวจสอบย้อนกลับ
Full Description / Objectives textarea วัตถุประสงค์การใช้งาน รายละเอียดการทดลอง สารเคมีที่ใช้ และข้อควรระวังในการเดินเครื่อง
Usage Type Radio Buttons เลือกประเภทงาน: Internal Project (โครงการวิจัยภายใน) หรือ External Commercial (งานบริการภายนอก)
Confirmation Status Select เลือกความแน่นอน: Confirmed (ยืนยันแน่นอน) หรือ Tentative (จองไว้ก่อนเบื้องต้น - แสดงแถบโปร่งแสงในปฏิทิน)
Repeat / Recurring Select การทำซ้ำ: None, Daily (ทุกวัน), Weekly (ทุกสัปดาห์), Monthly (ทุกเดือน), Yearly (ทุกปี)
Repeat End Date date วันสิ้นสุดรอบการทำซ้ำ (จะแสดงขึ้นมาเมื่อเลือก Repeat ที่ไม่ใช่ None)
Skip Past Conflicts Checkbox ข้ามช่วงเวลาที่มีการจองซ้อน: หากเลือกระบบจะข้ามรอบวันที่ชนกับคิวผู้อื่น และจองรอบที่ว่างให้อัตโนมัติโดยไม่ล้มเหลว
Check Availability Button ตรวจสอบความว่างของเครื่องมือแบบเรียลไทม์ ตรวจจับทั้งคิวจองและตารางซ่อมบำรุงใน Lab Care+
Save Booking Button ยืนยันการจอง ระบบจะเล่นเสียง Success Chime บันทึกข้อมูล และส่งแจ้งเตือนเข้าสู่ระบบกระดิ่ง

3.3 การจองแบบวนซ้ำ (Recurring Bookings) และการข้ามช่วงเวลาที่ชน

สำหรับงานวิจัยที่ต้องเก็บข้อมูลต่อเนื่องทุกสัปดาห์:

  1. เลือกช่อง Repeat เป็น Weekly และกำหนด Repeat End Date
  2. ทำเครื่องหมายถูกที่ช่อง "Skip Past Conflicts"
  3. หากมีสัปดาห์ใดที่มีผู้อื่นจองเครื่องไว้ก่อนแล้ว ระบบจะแจ้งเตือนว่า "ข้ามรอบวันที่ XX/XX/XXXX เนื่องจากมีคิวจองซ้อน" และสร้างรายการจองในสัปดาห์อื่นๆ ที่ว่างให้ครบถ้วน

3.4 ฟอร์มบันทึกเวลาใช้งานจริงและส่งคืน (Finish Usage & Dynamic Checklist)

เมื่อผู้ใช้งานเดินไปยังเครื่องมือจริง:

  1. กดปุ่ม "Check In" เมื่อเริ่มเปิดเครื่องเพื่อบันทึกเวลาจริง (Actual Start)
  2. เมื่อเสร็จสิ้นการทดลอง คลิกปุ่ม "Finish Usage" หน้าต่างโมดอลจะเปิดขึ้น:
    • Dynamic Parameters: พารามิเตอร์เฉพาะที่ผู้ดูแลกำหนดไว้สำหรับเครื่องมือนั้น (เช่น อุณหภูมิ, ความเร็วรอบ, หลอด UV)
    • Actual End Time: เวลาปิดเครื่องจริง
    • Usage Details & Remarks: ข้อสังเกต สภาพความสะอาด และบันทึกข้อผิดพลาดระหว่างเดินเครื่อง
  3. คลิกปุ่ม "Complete & Return" สถานะเครื่องจะปรับกลับเป็น Ready พร้อมใช้งานทันที

3.5 การสแกน QR Code หน้าเครื่องมือ

ผู้ใช้งานสามารถใช้สมาร์ทโฟนหรือแท็บเล็ตกดปุ่ม QR Scan ที่มุมบนขวา เพื่อสแกนคิวอาร์โค้ดประจำเครื่อง ระบบจะเปิดฟอร์มจองหรือเช็กอินของเครื่องมือนั้นให้ทันทีโดยไม่ต้องค้นหารายชื่อ

4. คู่มือการใช้งาน MPIR Lab Care+

4.1 แดชบอร์ดภาพรวมและปฏิทินงานแบบ Responsive (Mobile/Tablet/Desktop)

รวบรวมสรุปสถานะการซ่อมบำรุง, เครื่องมือที่ใกล้ถึงกำหนดสอบเทียบ (Calibration Due ใน 30-60 วัน), กราฟแจกแจงค่าใช้จ่ายประจำปี และปฏิทินกำหนดการงานบำรุงรักษาแบบ Responsive:

  • Mobile (< 640px): ตารางปฏิทินปรับความสูงเป็น 54px ชิปแสดงผลกะทัดรัด ตัวย่อวัน S M T W T F S พร้อมปุ่ม +N more เพื่อเปิดดูรายการทั้งหมดในวันนั้นในรูปแบบหน้าต่างโมดอล
  • Desktop / Tablet (> 640px): แสดงตารางปฏิทินขนาดเต็ม พร้อมชื่อเครื่องมือและประเภทงาน
  • ปุ่ม "Today": คลิกเพื่อเลื่อนหน้าปฏิทินกลับมายังเดือนและวันที่ปัจจุบันได้ทันทีในคลิกเดียว

4.2 ระบบตัวกรองข้อมูลแบบโต้ตอบทันที (Instant Reactive Filters & Visual Cards)

แถบตัวกรอง Status, Service Type, Equipment, และ Location ด้านบนปฏิทิน ตอบสนองแบบทันที (0ms):

  • เมื่อคลิกเปลี่ยนตัวเลือกในดรอปดาวน์ ทั้งปฏิทินและกราฟสรุปด้านบนจะคำนวณและอัปเดตใหม่ทันที
  • ระบบจะแสดง Smart Recommendation Card แนะนำรายการเครื่องมือที่ควรจัดลำดับความสำคัญตามเงื่อนไขตัวกรอง

4.3 รายละเอียดฟอร์มบันทึกงานซ่อมและงานสอบเทียบ (Exhaustive Maintenance Record Form)

เมื่อคลิกปุ่ม "+ New Record" แบบฟอร์มบันทึกงานซ่อมบำรุงจะเปิดขึ้น:

ฟิลด์ / ปุ่มควบคุม คำอธิบายและการใช้งาน
Location / Building เลือกอาคารหรือห้องปฏิบัติการที่เครื่องมือตั้งอยู่
Equipment เลือกเครื่องมือวิทยาศาสตร์ที่ต้องการบันทึกประวัติ
Service Type เลือกประเภทงาน: Repair (งานซ่อม), Calibration (งานสอบเทียบ), PM (บำรุงรักษาเชิงป้องกัน), หรือ Spare parts (เปลี่ยนอะไหล่)
Service Date วันที่เข้าดำเนินการซ่อมหรือสอบเทียบ
Next Due Date วันครบกำหนดสอบเทียบรอบถัดไป (สำคัญมากสำหรับประเภท Calibration เพื่อใช้แจ้งเตือนล่วงหน้า)
Maintenance Cost ค่าใช้จ่ายในการดำเนินงาน (บาท) จัดรูปแบบตัวเลข tabular-nums ชัดเจน
Vendor / Technician ชื่อบริษัทคู่ค้าหรือชื่อช่างผู้เชี่ยวชาญภายนอกที่เข้าให้บริการ
Reporter ชื่อเจ้าหน้าที่หรือนักวิจัยผู้แจ้งซ่อม/ผู้ประสานงาน
Status สถานะงาน: Pending (รอดำเนินการ), In Progress (กำลังดำเนินการ), หรือ Complete (เสร็จสมบูรณ์)
PO & Cert Upload กล่องเลือกไฟล์เอกสาร PDF (รองรับสูงสุด 5 ไฟล์ต่อรายการ จัดเก็บเข้าสู่ IndexedDB)
Save Record บันทึกข้อมูล พร้อมตรวจสอบการชนซ้อนกับคิวจองใน Lab Book+ อัตโนมัติ

4.4 การแนบไฟล์ใบสั่งซื้อ (PO) และใบรับรองสอบเทียบ (Cert)

จัดเก็บลง IndexedDB ปลอดภัยสูงสุด: ไฟล์ PDF ทั้งหมดถูกแยกเก็บใน IndexedDB ประจำเครื่อง ไม่กินโควตาตัวอักษรของ Local Storage และสามารถกดปุ่ม "View PO" ในตารางเพื่อเปิดพรีวิวอ่านเอกสารได้ทันที

4.5 การตรวจสอบการชนกับคิวจองเครื่องมือ (Cross-App Conflict Alert)

เมื่อเจ้าหน้าที่บันทึกวันที่จะส่งซ่อมหรือสอบเทียบ ระบบจะตรวจสอบข้ามไปยังตารางจองของ Lab Book+ ทันที หากมีผู้อื่นจองเครื่องไว้ในวันเดียวกัน ระบบจะแสดง SweetAlert เตือนชื่อผู้จองและช่วงเวลาทันที เพื่อป้องกันปัญหาเครื่องถูกส่งซ่อมขณะกำลังมีงานวิจัยสำคัญ

4.6 การส่งออกรายงานสรุป (Export PDF & Excel)

  • Export to Excel (.xlsx): สำหรับนำไปวิเคราะห์คำนวณงบประมาณต่อในโปรแกรมสเปรดชีต พร้อมสูตรสรุปยอดรวม
  • Export to PDF: สร้างเอกสารรายงานทางการ พร้อมฟอนต์ภาษาไทย TH Sarabun New สวยงามพร้อมพิมพ์

5. คู่มือสำหรับผู้ดูแลระบบ (Admin Control Guide)

(สงวนสิทธิ์เฉพาะผู้ใช้งานที่มีสิทธิ์ Role: admin เท่านั้น)

5.1 การจัดการเครื่องมือวิทยาศาสตร์และฟิลด์พารามิเตอร์เฉพาะ

สามารถเพิ่ม แก้ไขหมายเลข Serial Number เปลี่ยนชื่อผู้ดูแลประจำเครื่อง (Custodian) หรือกำหนด Dynamic Parameters สำหรับให้ผู้ใช้กรอกตอนส่งคืนเครื่องมือ

5.2 การจัดการอาคารและห้องปฏิบัติการ

สามารถเพิ่มห้องปฏิบัติการใหม่ เช่น Pilot Plant Unit หรือ Fermentation Lab ข้อมูลจะถูกอัปเดตไปยังตัวเลือกของทั้งสองระบบทันที

5.3 การจัดการบัญชีผู้ใช้งานและสิทธิ์

สามารถเพิ่มรายชื่อนักวิจัยใหม่ กำหนดบทบาท (admin หรือ user) และรีเซ็ตรหัสผ่านได้ตลอดเวลา

5.4 การสำรองข้อมูลรวม 2 ระบบในคลิกเดียว (Unified Backup All)

สำรองและกู้คืนข้ามระบบ 100%

ในเวอร์ชัน 2.1 ทั้ง Lab Book+ และ Lab Care+ มีปุ่ม "Backup All (2 Systems)" ซึ่งจะรวมข้อมูลรายการจอง, ประวัติซ่อม, ข้อมูลเครื่องมือ, ผู้ใช้งาน และ ไฟล์แนบ PO ทั้งหมดใน IndexedDB เข้าเป็นไฟล์ JSON เดียว (LabSuite_Unified_Backup_YYYY-MM-DD.json)

การกด "Import Unified JSON" ในระบบใดระบบหนึ่ง จะกู้คืนและซิงค์ข้อมูลคืนสู่ทั้ง 2 ระบบและ IndexedDB พร้อมกันทันที

5.5 เครื่องมือเคลียร์ข้อมูลคืนพื้นที่ (Storage Cleanup & Quota Purge Tool)

เพื่อรักษาพื้นที่จัดเก็บบนคลาวด์ให้อยู่ในโควตาฟรี 1GB ของ Firebase Spark Plan และป้องกันความจำเบราว์เซอร์เต็ม:

การันตีความปลอดภัยสูงสุด (Master Data Immutability): ระบบจะลบเฉพาะ ประวัติการจอง (Bookings) และประวัติงานซ่อม (Records พร้อมไฟล์แนบ PO) ที่เก่ากว่าช่วงเวลาที่เลือกเท่านั้น ไม่มีทางลบข้อมูลเครื่องมือ, ห้องแล็บ, รายชื่อผู้ใช้ หรือรายชื่อช่างเด็ดขาด

ตัวเลือกช่วงเวลาที่สามารถล้างได้:

  • เก่ากว่า 1 เดือน (> 30 วันที่ผ่านมา)
  • เก่ากว่า 1 ไตรมาส (> 90 วันที่ผ่านมา - ค่าแนะนำ)
  • เก่ากว่า 6 เดือน (> 180 วันที่ผ่านมา)
  • เก่ากว่า 1 ปี (> 365 วันที่ผ่านมา)
  • เก่ากว่า 2 ปี (> 730 วันที่ผ่านมา)
  • ลบประวัติการใช้งานทั้งหมดของ User (ล้างกระดานเฉพาะ Transaction)

ก่อนการลบจริง ระบบจะแสดงหน้าต่างสรุปจำนวนรายการที่จะลบ พร้อมปุ่ม "💾 แบ็คอัพก่อนล้าง" เพื่อดาวน์โหลดไฟล์สำรองข้อมูลฉบับเต็มเก็บไว้ก่อนเสมอ

5.6 การเชื่อมต่อ Cloud Database (Firebase Spark Plan 100% Free)

ผู้ดูแลระบบสามารถเปิดใช้งาน Cloud Real-time Synchronization ในแพ็กเกจฟรีได้ง่ายๆ:

  1. ไปที่ Firebase Console สร้างโปรเจกต์ใหม่ (แผน Spark ฟรี ไม่ต้องใช้บัตรเครดิต)
  2. สร้างฐานข้อมูล Cloud Firestore
  3. ไปที่ Project Settings > General > Your apps เลือก Web App (</>) เพื่อคัดลอกค่า Config
  4. คลิกปุ่ม "Cloud Config" ในหน้าต่าง Admin กรอก API Key และ Project ID แล้วกด "บันทึกและเชื่อมต่อ"
  5. ระบบจะแสดงสถานะ Connected (Spark Plan) สีเขียว และซิงค์ข้อมูลขึ้นคลาวด์แบบเรียลไทม์ หากออฟไลน์ระบบจะสลับเป็น Local-First อัตโนมัติโดยข้อมูลไม่สูญหาย

โหมดเชื่อมต่ออัตโนมัติ (Zero-Config Auto-Connect)

ผู้ดูแลระบบสามารถนำค่า apiKey และ projectId ไปใส่ไว้ใน DEFAULT_CONFIG ของไฟล์ shared-core.js เพียงครั้งเดียว ผู้ใช้งานคนอื่นๆ บนเครื่องอื่นจะไม่ต้องกรอกค่าใดๆ เลย ระบบจะเชื่อมต่อไปยัง Firebase Cloud ให้โดยอัตโนมัติทันที

การบีบอัดไฟล์แนบขั้นสูงสุด (Maximum Compression & Cloud Attachments)

ไฟล์แนบ PDF ที่อัปโหลดจะถูกบีบอัดด้วย Native Gzip Web Streams API ลดขนาดลง 50% - 80% ทันที และจัดเก็บใน Cloud Firestore คอลเลกชัน lab_attachments พร้อมให้ผู้ใช้คนอื่นเปิดดูแบบ On-Demand และรวมอยู่ในไฟล์สำรองข้อมูล (Backup) แบบบีบอัดเรียบร้อย

6. คำถามที่พบบ่อย (FAQ & Troubleshooting)

ปัจจุบันระบบเวอร์ชัน 2.0 รองรับทั้งชื่อผู้ใช้สั้น (เช่น Saranyap หรือ admin) และอีเมลเต็มรูปแบบแล้ว ตรวจสอบรหัสผ่านเริ่มต้นคือ user123 (หรือ admin321 สำหรับแอดมิน)
บนหน้าจอโทรศัพท์ขนาดเล็ก (< 768px) ระบบจะแสดง Mobile Bottom Navigation Bar ทางด้านล่างของหน้าจออัตโนมัติ เพื่อให้กดเปลี่ยนหน้าด้วยนิ้วหัวแม่มือได้อย่างสะดวกสบาย
ในเวอร์ชัน 2.2 ไฟล์แนบ PDF ทุกไฟล์จะถูกบีบอัดด้วย Native Gzip Web Streams (LabCompressor) ลดขนาดลง 50% - 80% และอัปโหลดไปยังคอลเลกชัน lab_attachments บน Cloud Firestore อัตโนมัติ ผู้ใช้งานจึงสามารถเปิดดูเอกสารข้ามเครื่องหรืออุปกรณ์ได้ทันทีแบบ On-Demand Lazy Fetching โดยไม่ต้องกู้คืนข้อมูลแบบแมนนวล และยังสามารถสำรองข้อมูลรวมในไฟล์เดียวผ่านฟังก์ชัน Unified Backup ได้เสมอ
สามารถเปิดใช้งานผ่านโหมด Private / Incognito ของเบราว์เซอร์ หรือเคลียร์ Storage ของเบราว์เซอร์ ชุดข้อมูลจำลองมาตรฐาน (Seed Data) จะถูกโหลดกลับมาใหม่อัตโนมัติ

สถาปัตยกรรมระบบ (System Design Specification)

ข้อกำหนดทางสถาปัตยกรรม เทคโนโลยี สคีมาข้อมูล และหลักการยศาสตร์ด้านภาพ (Visual Ergonomics) สำหรับระบบ Lab Book+ & MPIR Lab Care+

Architecture: Unified Client-Side Multi-App
Storage Engine: LocalStorage + IndexedDB + Firebase Spark
Design Tokens: Color Theory 60-30-10

1. Executive Summary

MPIR Lab Suite เป็นแพลตฟอร์มบริหารจัดการทรัพยากรห้องปฏิบัติการวิจัยและทดลองแบบครบวงจร ภายใต้สถาปัตยกรรม **Unified Client-Side Architecture** โดยมีเป้าหมายหลักในการขจัดจุดบอดเดิม (Blind Spots) 3 ประการ:

  • Data Overwrite Elimination: ไม่ให้เกิดการเขียนทับข้อมูลข้ามระบบระหว่าง Lab Book+ และ Care+
  • ID Type Safety: ป้องกันข้อผิดพลาดจากการผสมผสานรหัสเครื่องมือที่เป็นตัวเลขและสตริง
  • Enterprise Domain Support: รองรับการยืนยันตัวตนของบุคลากรทั้งกลุ่มมิตรผลและผู้ใช้นอกเครือข่าย

5. State Synchronization Engine (LabStateBridge)

กลไก Deep Merge อัจฉริยะที่ป้องกันการสูญหายของข้อมูลระหว่างสองระบบ:

JavaScript: LabStateBridge Merge Logic 
// Data Merge & Normalization Guard
const merged = {
    ...currentStorage,
    ...cleanIncomingData,
    users: normalizedUsers,
    equipments: normalizedEquipments.map(e => ({ ...e, id: String(e.id) })),
    records: Array.isArray(incoming.records) ? incoming.records : currentStorage.records || [],
    bookings: Array.isArray(incoming.bookings) ? incoming.bookings : currentStorage.bookings || []
};
localStorage.setItem('NoteLabState_Merged', JSON.stringify(merged));
window.dispatchEvent(new CustomEvent('labStateChange', { detail: merged }));
  • Automatic String Casting: แปลงค่า ID ให้เป็นสตริงเสมอ ป้องกัน TypeError: startsWith is not a function
  • Key Preservation: เก็บรักษาฟิลด์เฉพาะของ CarePlus (เช่น records, technicians, reporters) ไม่ให้ถูก Lab Book+ บันทึกทับ

6.1 Web Audio API Synthesizer

  • Success Chime: คลื่นรูปไซน์ (Sine wave) ความถี่ 523.25Hz (C5) และ 783.99Hz (G5) Decay 0.3 วินาที
  • Click Sound: คลื่นรูปสามเหลี่ยม (Triangle wave) 800Hz สั้น 0.04 วินาที

7. Storage Management & Gzip Compression Pipeline

ในเวอร์ชัน 2.2 ระบบนำสถาปัตยกรรมบีบอัดขั้นสูง LabCompressor ด้วย Native Gzip Web Streams API มาใช้งานร่วมกับระบบจัดเก็บข้อมูลแบบ Multi-Tier: 

flowchart LR
    PDF[Original PDF File] --> Stream[ReadableStream]
    Stream --> Comp[CompressionStream 'gzip']
    Comp --> B64[Base64 Gzip String
50%-80% Size Reduction]
    B64 --> IDB[(Local Cache: IndexedDB)]
    B64 --> Cloud[(Cloud: lab_attachments/{recordId})]
  • Native Browser Gzip: ใช้ CompressionStream('gzip') และ DecompressionStream('gzip') โดยไม่ต้องพึ่งพา External Library ภายนอก ทำให้ทำงานเร็วระดับมิลลิวินาที
  • Dedicated Firestore Collection: แยกเก็บไฟล์แนบในคอลเลกชัน lab_attachments ไม่ปะปนกับคิวจองใน lab_suite/current_state ป้องกันปัญหา Document Size เกิน 1MB
  • On-Demand Lazy Fetching: โหลดไฟล์เฉพาะเมื่อผู้ใช้กดดูพรีวิว (Eye Icon) และคลายบีบอัดในหน่วยความจำเพื่อสร้าง Blob URL ให้ iframe แสดงผล ป้องกันการใช้เน็ตเวิร์กและแคชเกินจำเป็น
  • Unified Compressed Backup: เมื่อแอดมินส่งออก Backup ข้อมูลไฟล์แนบที่บีบอัดแล้วจะถูกแพ็กรวมเข้าสู่ไฟล์ JSON เดียวกันอย่างสมบูรณ์
