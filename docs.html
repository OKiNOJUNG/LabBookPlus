1. บทนำและภาพรวมการทำงานของ 2 ระบบ

MPIR Lab Suite เป็นแพลตฟอร์มบริหารจัดการทรัพยากรห้องปฏิบัติการวิจัยและทดลองแบบครบวงจรของฝ่ายวิจัยและนวัตกรรม กลุ่มมิตรผล โดยถูกออกแบบเป็น 2 ระบบที่ทำงานร่วมกันบนฐานข้อมูลกลางแบบเรียลไทม์:

1. Lab Book+ (Lab Equipment LogBook)

สำหรับนักวิจัย: ตรวจสอบตารางคิวเครื่องมือ จองเครื่องมือวิทยาศาสตร์แบบเดี่ยวหรือวนซ้ำ ข้ามช่วงเวลาที่ชน บันทึกเวลาเริ่ม-ส่งคืนจริง (Actual Usage) และสแกน QR Code หน้าเครื่อง

2. MPIR Lab Care+

สำหรับการดูแลรักษา: บันทึกประวัติแจ้งซ่อม (Repair) แผนสอบเทียบตามรอบ (Calibration) บำรุงรักษาเชิงป้องกัน (PM) แนบไฟล์ใบสั่งซื้อ/ใบรับรอง (PO/Cert) พร้อมระบบบีบอัดขั้นสูง

ทำงานประสานกันแบบ Zero-Config Auto-Connect: ผู้ใช้งานทุกคนเปิดเว็บบนคอมพิวเตอร์ แท็บเล็ต หรือสมาร์ทโฟน ระบบจะเชื่อมต่อคลาวด์ Google Cloud Firestore ให้ทันทีโดยไม่ต้องขอ API Key หรือตั้งค่าใดๆ และหากไม่มีสัญญาณเน็ต จะสลับเป็นโหมดออฟไลน์ทำงานต่อได้ทันที 100%

2. แผนผังลำดับการใช้งานของผู้ใช้งาน (User Journey Infographic)

ภาพรวมวงจรการทำงานตั้งแต่เริ่มต้นล็อกอิน ตรวจสอบคิว จองเครื่องมือ เข้าใช้งานจริง ส่งคืน ตลอดจนการแจ้งซ่อมและสอบเทียบ:

แผนผัง 8 ขั้นตอนการใช้งานระบบ MPIR Lab Suite (End-to-End Researcher Journey)
แผนภาพแสดงเส้นทางการใช้งาน 8 จุดหลัก แบ่งเป็น 2 เฟส: รอบการจองใช้งาน (Lab Book+) และรอบการบำรุงรักษา (Lab Care+) Interactive Vector SVG

3. ลำดับขั้นตอนการใช้งานจุดต่างๆ ของผู้ใช้งานอย่างละเอียด

รายละเอียดในแต่ละขั้นตอน เพื่อให้ผู้ใช้งานและนักวิจัยสามารถใช้งานฟังก์ชันของระบบได้อย่างถูกต้องและรวดเร็ว:

01
จุดที่ 1: การเข้าสู่ระบบและการสลับระบบ (SSO & Quick Switcher) Single Sign-On

ระบบออกแบบให้การเข้าใช้งานสะดวกสูงสุด โดยรองรับทั้งชื่อสั้นของนักวิจัย หรืออีเมลเต็มรูปแบบ พร้อมฟังก์ชันจำลองเซสชันข้ามหน้าจอ:

  • การล็อกอิน: กรอก Username เช่น Saranyap หรือ admin พร้อมรหัสผ่าน จากนั้นกด "Sign In"

  • โหมดมืด & เสียงตอบรับ: กดไอคอน เพื่อปรับโหมดมืดถนอมสายตา และกดไอคอน เพื่อเปิด/ปิดเสียงตอบรับการคลิก

02
จุดที่ 2: การสำรวจปฏิทินและตรวจสอบสถานะคิวเครื่องมือ Calendar & Status

หน้าหลักของ Lab Book+ แสดงปฏิทินแบบโต้ตอบ (Interactive Calendar) ช่วยให้นักวิจัยวางแผนการทดลองได้อย่างแม่นยำ:

  • การสลับมุมมอง: สามารถเลือกมุมมอง เดือน (Month), สัปดาห์ (Week), วัน (Day) ได้ที่มุมบนขวาของปฏิทิน
  • การกรองตามสถานที่และเครื่องมือ: เมนูดรอปดาวน์ด้านบนช่วยกรองตาม Area / Building และ Equipment ได้อย่างรวดเร็ว
  • การอ่านรหัสสีสถานะ:
    Booked (สีน้ำเงิน): มีผู้จองไว้ล่วงหน้า In Use (สีเหลืองกระพริบ): กำลังเปิดใช้งานจริงอยู่ขณะนี้ Finished (สีเขียว): ใช้งานเสร็จสิ้นและส่งคืนแล้ว Maintenance (สีแดง): เครื่องมืออยู่ระหว่างซ่อม/สอบเทียบ
  • การดูรายละเอียดคิว: คลิกที่รายการแถบสีบนปฏิทินเพื่อดูชื่อผู้จอง รหัสโครงการ และช่วงเวลาที่จอง
03
จุดที่ 3: ขั้นตอนการจองเครื่องมือวิทยาศาสตร์ (Equipment Booking) Exhaustive Guide

คลิกปุ่ม "+ Book Equipment" หรือคลิกบนช่องวัน/เวลาว่างบนปฏิทิน หน้าต่างแบบฟอร์มการจองจะเปิดขึ้น:

หน้าต่างแบบฟอร์มการจองเครื่องมือวิทยาศาสตร์ใน Lab Book+

รายละเอียดฟิลด์และการตั้งค่าในฟอร์มการจอง:

ฟิลด์ข้อมูล ประเภทข้อมูล พฤติกรรมและการทำงานอัตโนมัติ (Smart Features)
Area / Building Dropdown เลือกอาคารหรือห้องแล็บ ระบบจะกรองรายชื่อเครื่องมือในช่องถัดไปให้ตรงกับห้องทันที
Equipment Dropdown เลือกเครื่องมือวิทยาศาสตร์ที่ต้องการจอง พร้อมมีป้ายกำกับสถานะ เช่น Ready หรือ Maintenance
Start Date & Time Datetime-local Smart Auto-Round: ปัดเศษนาทีขึ้นเป็นต้นชั่วโมงถัดไปให้อัตโนมัติ เช่น 10:14 น. จะถูกตั้งเป็น 11:00 น.
End Date & Time Datetime-local Smart Default: ตั้งเวลาสิ้นสุดเริ่มต้นเป็น 2 ชั่วโมงถัดไปอัตโนมัติ
Project Code Text รหัสโครงการวิจัย เช่น RD-2026-MP01 เพื่อประโยชน์ในการติดตามงบประมาณ
Description / Notes Textarea ระบุรายละเอียดการทดลอง เช่น สารตัวอย่าง อุณหภูมิ หรือสภาวะพิเศษ
Usage Type Radio เลือกระหว่าง Internal Research (งานวิจัยภายใน) หรือ External Service (บริการวิเคราะห์ภายนอก)
Repeat Booking (จองวนซ้ำ) Dropdown รองรับ None, Daily (ทุกวัน), Weekly (ทุกสัปดาห์), Monthly (ทุกเดือน)
Repeat End Date Date ระบุวันสิ้นสุดรอบการจองวนซ้ำ เช่น กำหนดให้จองต่อเนื่อง 2 เดือน
Skip Past Conflicts Checkbox ฟังก์ชันเด่น: หากมีบางสัปดาห์ที่เครื่องมือติดคิวจองของผู้อื่น ระบบจะข้ามเฉพาะสัปดาห์นั้น และสร้างรายการจองในสัปดาห์อื่นที่ว่างให้จนครบโดยไม่แจ้ง Error ขัดจังหวะ
04
จุดที่ 4: การสแกน QR Code ประจำเครื่องมือ (QR Check-in) Mobile / Tablet

เมื่อนักวิจัยเดินเข้ามาถึงหน้าเครื่องมือวิทยาศาสตร์ในห้องปฏิบัติการ:

  1. เปิดเว็บผ่านสมาร์ทโฟนหรือแท็บเล็ต แล้วคลิกปุ่ม "QR Scanner" บนแถบเมนู
  2. อนุญาตให้เบราว์เซอร์เข้าถึงกล้องถ่ายภาพ
  3. นำกล้องไปส่องที่สติ๊กเกอร์ QR Code ที่ติดอยู่หน้าเครื่องมือวิทยาศาสตร์
  4. ระบบจะประมวลผลรหัสเครื่องมือ และเปิดหน้าต่างแบบฟอร์มการจอง หรือหน้าต่างเช็กอินเข้าใช้งานเครื่องมือนั้นให้ทันที 0 วินาที โดยไม่ต้องเลื่อนหารายชื่อเครื่องมือ
05
จุดที่ 5: การเข้าใช้งานจริง และขั้นตอนการส่งคืน (Finish Usage & Checklist) Dynamic Checklist

การบันทึกเวลาใช้งานจริงช่วยให้ห้องแล็บมีสถิติการใช้งานเครื่องมือที่ถูกต้องตามจริง:

  • เริ่มใช้งาน (Start Usage): เมื่อถึงเวลาใช้งาน ให้กดปุ่ม Start Usage เพื่อเปลี่ยนสถานะเป็น In Use เครื่องมือจะแสดงเป็นสีเหลืองกระพริบเพื่อแจ้งให้ผู้อื่นทราบว่ากำลังเดินเครื่องอยู่
  • ส่งคืนเครื่องมือ (Finish Usage): เมื่อการทดลองเสร็จสิ้น ให้คลิกปุ่ม "Finish Usage"
  • บันทึกเวลาจริง (Actual Times): ตรวจสอบเวลาเริ่มจริง (Actual Start) และเวลาเสร็จจริง (Actual End)
  • Dynamic Parameter Checklist: ระบบจะแสดงหัวข้อตรวจเช็กเฉพาะตามประเภทเครื่องมือ เช่น:
    • เครื่องปั่นเหวี่ยง (Centrifuge): บันทึกรอบความเร็วรอบสูงสุด (RPM) และเช็กความสมดุลโรเตอร์
    • เครื่องหมัก (Fermenter): บันทึกปริมาตรสารอาหาร และเช็กระดับแรงดัน DO / pH
    • เครื่อง HPLC / GC: บันทึกแรงดันคอลัมน์ และปริมาณตัวทำละลายที่ใช้
    • ตู้ชีวนิรภัย (Biosafety Cabinet): บันทึกชั่วโมงการเปิดหลอด UV และการทำความสะอาดพื้นผิวด้วย 70% Ethanol
  • กดปุ่ม "Complete & Return Equipment": สถานะเครื่องมือจะเปลี่ยนเป็น Finished และสถานะเครื่องมือหลักจะกลับสู่ Ready พร้อมให้ผู้อื่นใช้งานต่อทันที
06
จุดที่ 6: การแจ้งซ่อมบำรุงและวางแผนสอบเทียบใน Lab Care+ Lab Care+ Workflow

เมื่อเครื่องมือเกิดข้อขัดข้อง หรือถึงรอบสอบเทียบมาตรฐานประจำปี ให้สลับไปที่ MPIR Lab Care+:

  • คลิกปุ่ม "+ New Record" เพื่อสร้างบันทึกประวัติการบำรุงรักษาใหม่
  • Service Type: เลือกระหว่าง:
    • Repair: งานซ่อมแซมกรณีเครื่องมือชำรุดเสียหาย
    • Calibration: งานสอบเทียบมาตรฐานความถูกต้องของเครื่องมือตามข้อกำหนด ISO/IEC 17025
    • PM (Preventive Maintenance): งานบำรุงรักษาเชิงป้องกันตามรอบระยะเวลา
  • Service Date: ระบุวันที่ดำเนินการเข้าซ่อมหรือสอบเทียบ
  • Next Due Date (วันครบกำหนดรอบถัดไป): สำคัญมากสำหรับการสอบเทียบ ระบบจะนำวันเวลานี้ไปคำนวณและแสดงการแจ้งเตือนล่วงหน้า 30-60 วัน ก่อนที่ใบเซอร์จะหมดอายุ
  • Maintenance Cost: ระบุค่าบริการและค่าอะไหล่ (บาท) เพื่อนำไปสรุปงบประมาณ
  • Cross-App Conflict Alert: หากวัน Service Date ชนกับช่วงเวลาที่มีนักวิจัยจองไว้ใน Lab Book+ ระบบจะแสดงหน้าต่างแจ้งเตือนทันที เพื่อให้ประสานงานเลื่อนคิวได้อย่างราบรื่น
แดชบอร์ด Lab Care+ และฟอร์มบันทึกพร้อมตัวแสดงเปอร์เซ็นต์บีบอัดไฟล์

    • หากเปิดดูจากเครื่องคอมพิวเตอร์หรือมือถือเครื่องอื่น ระบบจะดาวน์โหลดไฟล์บีบอัดจาก Cloud และคลายการบีบอัดในหน่วยความจำทันที พร้อมเปิดแสดงผลในหน้าต่างพรีวิวอย่างคมชัด 100%
    • ไฟล์จะถูกบันทึกแคชไว้ในเครื่องนั้น ทำให้การเปิดดูครั้งต่อไปรวดเร็วโดยไม่ต้องดาวน์โหลดซ้ำ

  • Restore Unified JSON: เลือกไฟล์ Backup ระบบจะตรวจสอบความถูกต้อง และเขียนข้อมูลคืนสู่ทั้ง Local Storage, IndexedDB และ Cloud Firestore ให้อัตโนมัติ

การันตีความปลอดภัยของ Master Data (Master Data Immutability Guarantee): เครื่องมือล้างข้อมูลเก่านี้จะทำการลบเฉพาะ ประวัติการจองเก่า (Bookings) และ ประวัติงานซ่อมเก่า (Records) ตามระยะเวลาที่แอดมินเลือกเท่านั้น (เช่น เก่ากว่า 90 วัน) โดย ไม่มีทางลบ ทะเบียนเครื่องมือ, อาคาร, ห้องแล็บ, รายชื่อผู้ใช้ หรือรายชื่อช่างโดยเด็ดขาด 100%

1. Executive Summary & Design Principles

MPIR Lab Suite v2.2 พัฒนาขึ้นภายใต้หลักการ Zero-Dependency Vanilla Architecture เพื่อความทนทาน เสถียรภาพสูงสุด และต้นทุนการดูแลรักษาระยะยาวเป็น 0 บาท โดยมีหลักการออกแบบหลัก 4 ประการ:

1. Local-First Resilience

ข้อมูลทุกอย่างทำงานบนเบราว์เซอร์เป็นหลัก แม้ระบบเครือข่ายภายนอกล่ม ผู้ใช้งานในแล็บยังคงทำงานและบันทึกข้อมูลได้อย่างราบรื่น 100%

2. Safe Deep Merge

ลบความเสี่ยงข้อมูลสูญหายจากการเขียนทับข้ามแอป ด้วย LabStateBridge ที่รักษาคีย์เฉพาะของแต่ละระบบไว้อย่างสมบูรณ์

3. Stream Compression

บีบอัดไบนารี PDF ด้วย Native Browser Gzip Streams ลดขนาดข้อมูลลง 50-80% ช่วยให้ไม่เกินเพดานโควตาฟรีของคลาวด์

4. Zero-Config Cloud

รวม Credentials ใน shared-core.js ให้เชื่อมต่อ Firestore ทันที โดยที่ End-User ไม่ต้องผ่านขั้นตอนการ Setup

4. State Synchronization Engine (`LabStateBridge`)

หัวใจสำคัญของการป้องกันข้อมูลชนกันข้ามแท็บคือกลไก Safe Deep Merge & String ID Normalization:

JavaScript: State Merge & Key Preservation Guard 
// Data Merge & Normalization Guard in shared-core.js
mergeState(incoming) {
    const current = this.loadLocalState() || {};
    const normalizedEquipments = (incoming.equipments || current.equipments || []).map(e => ({
        ...e,
        id: String(e.id) // Automatic String ID casting to prevent runtime exceptions
    }));

    const merged = {
        ...current,
        ...incoming,
        users: incoming.users || current.users || [],
        equipments: normalizedEquipments,
        records: Array.isArray(incoming.records) ? incoming.records : current.records || [],
        bookings: Array.isArray(incoming.bookings) ? incoming.bookings : current.bookings || [],
        technicians: incoming.technicians || current.technicians || [],
        reporters: incoming.reporters || current.reporters || [],
        lastSync: new Date().toISOString()
    };

    localStorage.setItem('NoteLabState_Merged', JSON.stringify(merged));
    window.dispatchEvent(new CustomEvent('labStateChange', { detail: merged }));
    return merged;
}
  • Cross-Tab Sync: เมื่อหน้าต่างใดบันทึกข้อมูล จะยิงอีเวนต์ window.storage ทำให้แท็บอื่นอัปเดตข้อมูลขึ้นหน้าจอทันที
  • Safe Type Casting: แปลงรหัสเครื่องมือเป็นสตริงเสมอ ป้องกัน TypeError: startsWith is not a function

5. Gzip Streams Compression Pipeline (`LabCompressor`)

การบีบอัดไบนารีระดับ Browser Streams โดยไม่ต้องพึ่งไลบรารีภายนอก (Zero External Dependencies):

แผนภาพกระบวนการบีบอัดไฟล์ PDF ด้วย Web Streams API
JavaScript: Native Browser Gzip Pipeline 
// Native Web Streams Compression in LabCompressor
async compressPdf(file) {
    const stream = file.stream();
    const compressedStream = stream.pipeThrough(new CompressionStream('gzip'));
    const response = new Response(compressedStream);
    const blob = await response.blob();
    const base64 = await this.blobToBase64(blob);
    return {
        name: file.name,
        compressedData: base64,
        originalSize: file.size,
        compressedSize: blob.size,
        reductionPercent: Math.round(((file.size - blob.size) / file.size) * 100)
    };
}

11. Netlify Production Deployment & Caching Guard

เพื่อให้มั่นใจว่าผู้ใช้งานจะได้รับโค้ดเวอร์ชันล่าสุดเสมอ ไม่ติดแคชเบราว์เซอร์เก่า:

  • ไฟล์ _headers: กำหนด Cache-Control: public, max-age=0, must-revalidate สำหรับไฟล์ HTML, JS และ CSS
  • ไฟล์ _redirects: กำหนด Route Rewrites ให้เรียกใช้งานผ่าน URL สั้นได้ เช่น /careplus, /docs, /book

12. Verification & Quality Assurance Matrix

  • Zero-Crash Persistence: รองรับ ID เครื่องมือทั้งตัวเลข (เช่น 12) และสตริง (เช่น EQ-001) ผ่านการทดสอบ 100%
  • Master Data Immutability: ทดสอบการ Purge Retention ข้อมูล Master (Users, Equipments, Buildings) คงอยู่ครบถ้วน
  • Multi-Device Lazy Preview: ทดสอบการเปิดดู PO บนเครื่องที่ไม่มีไฟล์ต้นฉบับ สามารถดาวน์โหลดและคลายบีบอัดแสดงผลสำเร็จ
  • Theme & Audio Responsiveness: สลับโหมดมืดและเสียงสังเคราะห์ทำงานเป็นธรรมชาติบนทุกเบราว์เซอร์
